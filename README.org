#+title: org-defuddle

~org-defuddle~ is intended to be a Rust rewrite of [[https://github.com/kepano/defuddle][kepano/defuddle]] with an
Emacs dynamic module frontend that inserts extracted readable content into Org.

The current reference snapshot is upstream commit ~319cc98~ (0.19.9), pinned in
~tests/upstream-revision~. The long-term goal is feature parity with defuddle's extraction pipeline: metadata, schema.org fallback, DOM cleanup, scoring, site-specific
extractors, media handling, footnotes, math/code normalization, and Org content
conversion.

* Architecture

- ~crates/org-defuddle-core~: Rust extraction core. It owns HTML parsing, DOM
  cleanup, metadata extraction, content scoring, and HTML-to-Org conversion.
- ~crates/org-defuddle-module~: Emacs dynamic module exposing coarse-grained
  calls into the Rust core.
- ~crates/org-defuddle-cli~: Rust command-line wrapper for URL, file, and stdin
  parsing with Org default output plus JSON, frontmatter, property-style, and
  compatibility Markdown output.
- ~org-defuddle.el~: Emacs package frontend for loading the module,
  fetching URLs, parsing buffers, and inserting Org.

The module returns extracted metadata, cleaned HTML, and Org through
~org-defuddle-parse-html~. Parsing stays in Rust; URL retrieval and buffer/note
creation stay in the frontends.

* Installation

Requirements:

- Emacs 27.1 or newer with dynamic module support.
- macOS, GNU/Linux, or Windows on a supported architecture.

GNU/Linux release binaries are built on Ubuntu 20.04 and require glibc 2.31 or
newer.

Install the Elisp package from the repository, then run an interactive
org-defuddle command:

#+begin_src emacs-lisp
(use-package org-defuddle
  :vc (:url "https://github.com/LuciusChen/org-defuddle"
       :rev :newest))
#+end_src

On first interactive use, org-defuddle offers to download the pinned pre-built
Rust module from GitHub Releases.  The module is installed under
~user-emacs-directory/modules/~, verified against the release ~SHA256SUMS~
manifest, and loaded immediately.  Installation can also be triggered
explicitly:

#+begin_src emacs-lisp
M-x org-defuddle-download-module
#+end_src

Release binaries are published for:

- ~aarch64-apple-darwin~ (Apple Silicon)
- ~x86_64-apple-darwin~ (Intel macOS)
- ~aarch64-unknown-linux-gnu~
- ~x86_64-unknown-linux-gnu~
- ~x86_64-pc-windows-msvc~

The downloaded filename includes the pinned release version, using the pattern
~liborg_defuddle_module-<version>.dylib~.  Versioned filenames prevent a package
upgrade from silently loading an older native module.  Customize
~org-defuddle-module-file~ to use a different persistent location.

* Building From Source

Building requires Rust 1.80 or later and is only needed for development or an
unsupported release platform. Atom feed parsing uses ~roxmltree~ alongside the
HTML parser; Node is needed only to build the independent upstream test reference.

#+begin_src sh
cargo build --release -p org-defuddle-module
cargo build --release -p org-defuddle-cli
#+end_src

The compiled module is expected at one of:

- macOS: ~target/release/liborg_defuddle_module.dylib~
- GNU/Linux: ~target/release/liborg_defuddle_module.so~
- Windows: ~target/release/org_defuddle_module.dll~

The CLI binary is built at ~target/release/org-defuddle~.

Repository-local release builds are detected as a development fallback when no
downloaded module exists.  Tagged GitHub Releases also contain pre-built CLI
assets named ~org-defuddle-cli-<target>~.

* Emacs Usage

#+begin_src emacs-lisp
(add-to-list 'load-path "~/repos/org-defuddle")
(require 'org-defuddle)

(org-defuddle-url-to-org "https://example.com/post")
#+end_src

By default, extracted Org opens in a temporary buffer.  Configure an optional
note backend to create a Denote or Org-roam note instead:

#+begin_src emacs-lisp
;; Keep the default behavior.
(setq org-defuddle-output-backend 'buffer)

;; Or create a Denote note.
(setq org-defuddle-output-backend 'denote)

;; Or create an Org-roam note.
(setq org-defuddle-output-backend 'org-roam)
#+end_src

Denote and Org-roam remain optional dependencies and are loaded only when their
backend is selected.  Use ~org-defuddle-note-keywords~ for note tags and
~org-defuddle-denote-directory~ or ~org-defuddle-org-roam-file-name~ to
customize the destination.

** Literal markup characters

Org has no backslash escape for emphasis markers, so text such as ~/Agent/~,
~*do*~ or ~(/ɪɡˈzæmpəl/)~ would be rendered as italic or bold with the markers
hidden. When an opening ~*~, ~/~, ~_~, ~+~, ~=~ or ~~~ in page text would be
closed by a later marker of the same kind, org-defuddle puts a zero-width space
(U+200B) after it, as the Org manual suggests. This applies to body text and
the headline; code, URLs, real emphasis and property values such as
~:DESCRIPTION:~ are left alone, so ~org-entry-get~ returns the original string. The rules follow ~org-emphasis-regexp-components~ with non-ASCII
characters allowed next to the markers, which is how many people configure Org
for CJK text, so the output is safe with that setting and with the default one.

Each piece of text is checked on its own. If the two markers of a pair sit in
different inline elements with nothing between them, for example
~<span>/Agent</span>/ was~, neither piece is escaped and Org can still read the
pair as emphasis. The renderer usually puts a space between adjacent inline
elements, which keeps most such pairs from forming.

** Extraction options

Images are included by default.  To omit images from extracted Org output:

#+begin_src emacs-lisp
(setq org-defuddle-include-images nil)

;; Or override per call:
(org-defuddle-html-to-org html "https://example.com/article" '(:include-images nil))

;; Upstream-compatible inverse spelling:
(org-defuddle-html-to-org html "https://example.com/article" '(:remove-images t))
#+end_src

Small images and unresolved image placeholders are removed by default.  To keep
them:

#+begin_src emacs-lisp
(setq org-defuddle-remove-small-images nil)

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:remove-small-images nil))
#+end_src

To bypass automatic main-content detection and use a specific CSS selector:

#+begin_src emacs-lisp
(setq org-defuddle-content-selector "article.post-content")

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:content-selector "main article"))
#+end_src

Site-specific replies and comments are included by default.  To omit them:

#+begin_src emacs-lisp
(setq org-defuddle-include-replies nil)

;; Or override per call:
(org-defuddle-html-to-org html "https://example.com/post" '(:include-replies nil))
#+end_src

API transcript extractors use a stable default language order.  To prefer a
specific language where the site exposes multiple tracks:

#+begin_src emacs-lisp
(setq org-defuddle-language "en")

;; Or override per URL call:
(org-defuddle-url-to-org "https://www.bilibili.com/video/BV1nNkFBMEDS"
                         '(:language "zh-cn"))

(org-defuddle-url-to-org "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
                         '(:language "en"))
#+end_src

The language option ranks subtitle tracks already exposed by the video service;
it does not transcribe audio. YouTube selection follows the default audio track
and its default caption index, then the original language (with manual captions
preferred within that language), regional English, and remaining tracks. An
explicit language takes precedence. Inline player data from another video is
rejected. When a YouTube video has no caption track,
extraction falls back to the video metadata and description without a
transcript.

URL extraction uses supported site APIs and alternate hosts by default for
content that is not usually present in raw HTML, such as YouTube/Bilibili
transcripts and Reddit comments.  To force the original URL HTML path:

#+begin_src emacs-lisp
(setq org-defuddle-use-async nil)

;; Or override per URL call:
(org-defuddle-url-to-org "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
                         '(:use-async nil))
#+end_src

HTML standardization is enabled by default.  To preserve more of the original
HTML structure before Org rendering:

#+begin_src emacs-lisp
(setq org-defuddle-standardize nil)

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:standardize nil))
#+end_src

Debug and profiling diagnostics are disabled by default.  To include upstream
style debug/profile fields in JSON output:

#+begin_src emacs-lisp
(org-defuddle-parse-html html
                         "https://example.com/article"
                         '(:debug t :profile t))
#+end_src

YAML frontmatter is omitted by default.  To prepend upstream-style frontmatter
to Org output:

#+begin_src emacs-lisp
(setq org-defuddle-frontmatter t)

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:frontmatter t))
#+end_src

To extract a single upstream-style response property:

#+begin_src emacs-lisp
(org-defuddle-parse-html-property html
                                  "title"
                                  "https://example.com/article")

(org-defuddle-parse-html-property html
                                  "wordCount"
                                  "https://example.com/article")
#+end_src

Hidden elements are removed by default.  To preserve hidden content:

#+begin_src emacs-lisp
(setq org-defuddle-remove-hidden-elements nil)

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:remove-hidden-elements nil))
#+end_src

Known noise selectors are removed by default.  To preserve exact or partial
selector matches:

#+begin_src emacs-lisp
(setq org-defuddle-remove-exact-selectors nil)
(setq org-defuddle-remove-partial-selectors nil)

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:remove-exact-selectors nil
                            :remove-partial-selectors nil))
#+end_src

Content-pattern cleanup is enabled by default.  To preserve read-time labels,
related sections, and similar pattern-matched blocks:

#+begin_src emacs-lisp
(setq org-defuddle-remove-content-patterns nil)

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:remove-content-patterns nil))
#+end_src

Low-scoring block removal is enabled by default.  To preserve blocks that look
like navigation, recommendation, or listing clutter:

#+begin_src emacs-lisp
(setq org-defuddle-remove-low-scoring nil)

;; Or override per call:
(org-defuddle-html-to-org html
                          "https://example.com/article"
                          '(:remove-low-scoring nil))
#+end_src

For local HTML:

#+begin_src emacs-lisp
(with-temp-buffer
  (insert-file-contents "article.html")
  (org-defuddle-buffer-to-org "https://example.com/article"))
#+end_src

* CLI Usage

The Rust CLI supports upstream-style ~parse~ options for URLs, local HTML
files, and stdin:

#+begin_src sh
target/release/org-defuddle parse https://example.com/post
target/release/org-defuddle parse article.html
target/release/org-defuddle parse article.html --json
target/release/org-defuddle parse article.html --markdown
target/release/org-defuddle parse article.html --separate-markdown --json
target/release/org-defuddle parse article.html --frontmatter
target/release/org-defuddle parse article.html --property title
target/release/org-defuddle parse article.html --property contentMarkdown
target/release/org-defuddle parse article.html --output article.org
target/release/org-defuddle fetch https://example.com/api --header 'Accept: application/json'
#+end_src

CLI URL fetching includes a defuddle-style user agent, optional
~--user-agent~, optional ~--lang~ as ~Accept-Language~, HTML content-type
validation, a 5MB response limit, redirects, charset decoding, proxy
environment variables, and ~NO_PROXY~ matching. The ~fetch~ subcommand exposes
the same fetch stack for JSON/XML/text API helper requests with custom method,
headers, body, user agent, and language. If a URL extraction is empty and the
user did not set ~--user-agent~, the CLI retries once with defuddle's bot user agent and can
recover raw Markdown from the pre-DOM response body.

CLI ~parse~ orchestrates C2, X/Twitter, YouTube and Bilibili APIs, plus Reddit
alternate-host/Atom retrieval. Use ~--no-async~ to fetch the original HTML
instead. The ~fetch~ subcommand exposes the underlying HTTP transport.

* Upstream Alignment

Org is the primary output. The reference is Defuddle 0.19.9, pinned by
~tests/upstream-revision~. Passing its fixture corpus establishes behavior for
those inputs; it does not establish complete feature parity on live sites.

| Area | Coverage at the pinned baseline | Remaining difference |
|------+---------------------------------+----------------------|
| Canonical Org body | All 246 upstream final HTML fragments render to the same Org as Rust extraction | Pages and browser states outside the corpus are not covered |
| Main metadata | All 246 expected titles, authors, sites, and publication dates match | Other response fields need separate comparison |
| JSON response | Upstream field names, schema.org data, meta tags, extractor identity and variables are exposed | Description, domain, image, language, favicon, extractor identity and custom variables are not fully identical |
| HTML cleanup and scoring | Selector tables, content patterns, schema text recovery, media, code, math, footnotes, tables, SSR and serialized shadow DOM are implemented | Intermediate HTML is not an exact parity contract |
| Site extractors | Rust paths exist for all 26 registered upstream extractor classes | Existence is not proof of complete behavior or live API reliability |
| URL/API extraction | CLI and Emacs orchestrate C2, X/Twitter, YouTube, Bilibili and Reddit | Specialized API paths do not support all generic HTML options; live service availability is not guaranteed |
| Word count | All 246 ~wordCount~ results match the upstream reference | Inputs outside the corpus require separate verification |
| Markdown | All 246 outputs match upstream semantics through an independent CommonMark parser | HTML attribute order and insignificant serialization whitespace may differ |
| Debug/profile | Generic pipeline stages and selected removal records are exposed | Removal/error details and timings are not identical |
| Browser execution | Serialized DOM, inline player data and fetched API payloads are supported | No JavaScript execution, computed external CSS, transcript-panel clicks or dynamic DOM waits |

The site paths cover X articles/posts/oEmbed, Reddit, Hacker News, GitHub,
LinkedIn, Threads, Bluesky, Mastodon, Discourse, LWN, Substack, Medium, New York
Times, Wikipedia, C2 Wiki, LeetCode, Steam BBCode, ChatGPT, Claude, Gemini,
Grok, Gmail, YouTube, and Bilibili. GNU Debbugs extraction and Org note backends
are additional org-defuddle features. JavaScript package entry points and live
browser DOM APIs are platform-specific upstream surfaces rather than Rust APIs.

A broader offline comparison of the 246 fixtures found 14 description
mismatches, 4 image mismatches, and 1 language mismatch. Favicon defaults and
JSON-LD graph/meta-tag serialization have been corrected; favicon differences
remain on seven site-extractor responses and five relative-URL normalization
cases. Domain, extractor selection and custom variables also differ on some fixtures,
including fixtures with synthetic URLs. These observations are separate from
the four-field metadata gate above. ~schemaOrgData~ and ~metaTags~ are
available in JSON responses but not through single-property selection.

The independent output gate checks exact Org body text, exact ~wordCount~ and
Markdown semantics in one pass over the pinned corpus. Markdown comparison
preserves prose, code contents and language, math tokens and literal text,
footnote definitions, tables, and meaningful line breaks. Inline code preserves
internal whitespace and literal backticks. Literal math stays inert when the
Markdown consumer does not support math. The comparison ignores HTML
attribute order, insignificant blank lines around display math, and spacing
before punctuation and footnote markers. The CommonMark parser is a test-only
dependency and is compatible with Rust 1.80; it is not part of extraction at
runtime.

Compatible Emacs URL options use the CLI for the complete API flow; installations without a CLI retain the
module and Elisp fetch paths. API results honor Markdown and frontmatter output.

YouTube supports existing desktop/mobile transcript DOM, validated inline
~ytInitialPlayerResponse~ tracks, Innertube clients, timedtext and chapters.
Caption selection honors the default audio track, original language, manual
captions and explicit language preference. It cannot open a missing transcript
panel. Reddit prefers valid old-host HTML, then Atom on fetch failure or a
login/blocked page; malformed feeds surface errors. Atom preserves text and
image/reply controls but provides neither vote counts nor comment nesting.

* Testing

Rust and Emacs unit/regression tests run without Node. Upstream fixture tests
also require a local checkout containing the pinned HTML inputs; the checked-in
Org snapshots alone are insufficient. Without a checkout, those tests are
skipped. Set the path explicitly when claiming full fixture coverage:

#+begin_src sh
export ORG_DEFUDDLE_DEFUDDLE_DIR=/absolute/path/to/defuddle
git -C "$ORG_DEFUDDLE_DEFUDDLE_DIR" fetch origin "$(cat tests/upstream-revision)"
git -C "$ORG_DEFUDDLE_DEFUDDLE_DIR" checkout --detach "$(cat tests/upstream-revision)"

cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo +1.80.0 check --workspace --all-targets --locked
cargo test --workspace --locked
cargo build --release -p org-defuddle-module --locked
cargo build --release -p org-defuddle-cli --locked
emacs --batch -Q --eval '(byte-compile-file "org-defuddle.el")'
emacs --batch -Q --eval '(progn (require (quote checkdoc)) (find-file "org-defuddle.el") (checkdoc-current-buffer t))'
emacs --batch -Q -L . -L test -l test/org-defuddle-test.el -f ert-run-tests-batch-and-exit
#+end_src

Every fixture test validates the checkout revision and fixture count, including
when run individually. Exact Org snapshots under ~tests/expected-org/~ cover
the whole corpus; focused Rust and Emacs tests cover additional bugs, options,
API payloads, installation, fetching, and module/wrapper calls. The release
workflow reads the same pin and runs the checks above plus the independent output
differential before building release assets.

The independent differential needs the upstream Node build. It disables network
requests and compares upstream and Rust final content independently of the
checked-in Org snapshots:

#+begin_src sh
npm --prefix "$ORG_DEFUDDLE_DEFUDDLE_DIR" ci
npm --prefix "$ORG_DEFUDDLE_DEFUDDLE_DIR" run build:node
cargo test -p org-defuddle-core --test upstream_fixtures --locked \
  all_upstream_fixture_outputs_match_reference -- --ignored
#+end_src

Set ~ORG_DEFUDDLE_DIFF_FIXTURE=<fixture-name>~ on that command to inspect one
fixture. All three output comparisons are required release gates.

Org snapshots are local regression baselines, not independent parity evidence.
After the independent differential passes, regenerate them only for an
intentional output change:

#+begin_src sh
ORG_DEFUDDLE_UPDATE_EXPECTED_ORG=1 cargo test -p org-defuddle-core \
  --test upstream_fixtures all_upstream_fixture_org_regression_snapshots
#+end_src
